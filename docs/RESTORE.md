# Регламент резервного копирования и восстановления данных (VoltGroup)

Документ описывает процедуру автоматического создания резервных копий Google Таблицы объектов и регламент восстановления данных при ошибочных действиях или сбоях.

---

## 1. Где и как создаются резервные копии

- **Скрипт:** [`tools/backup.py`](../tools/backup.py).
- **Данные:** Выгружает все строки рабочего листа `sheet1` через сервисный аккаунт Google (`GOOGLE_CREDENTIALS`, `SHEET_URL`).
- **Форматы хранения:**
  1. `backups/backup_YYYYMMDD_HHMMSS.json` — структурированный снимок с метаданными (время создания, общее количество строк, исходная матрица данных).
  2. `backups/backup_YYYYMMDD_HHMMSS.csv` — табличный формат с разделителем `;` (UTF-8 with BOM) для прямого просмотра и импорта в Excel или Google Таблицы.
- **Ротация:** Скрипт автоматически хранит **последние 30 снимков**, удаляя более ранние копии. Каталог `backups/` исключён из Git (`.gitignore`).
- **Оповещения:** При сбое выгрузки скрипт отправляет алерт в Telegram администратору бота (`CHAT_ID`).

---

## 2. Ручной и плановый запуск

### 2.1. Ручной запуск
В терминале сервера или локально (при наличии `.env` или переменных окружения):
```bash
python tools/backup.py
```
С флагом уведомления в Telegram об успехе:
```bash
python tools/backup.py --notify-success
```

### 2.2. Плановый запуск (Cron / Сервер)
Для ежедневного запуска в 03:00 ночи добавьте запись в crontab:
```bash
0 3 * * * cd /path/to/voltgroup && python3 tools/backup.py >> logs/backup.log 2>&1
```

## 3. Регламент восстановления данных

Если оператор бота случайно обнулил оплату, удалил строку объекта или повредил данные в Google Таблице:

### Вариант А: Быстрый откат через встроенную историю версий Google Таблицы
1. Откройте рабочую Google Таблицу по ссылке `SHEET_URL`.
2. В верхнем меню выберите **Файл** → **Журнал версий** → **Посмотреть журнал версий** (`Ctrl+Alt+Shift+H`).
3. Найдите версию до ошибочного действия и восстановите её либо скопируйте нужную ячейку/строку.

### Вариант Б: Восстановление из локального резервного файла (CSV / JSON)
1. Откройте папку `backups/` на сервере или в локальной копии.
2. Найдите снимок с меткой времени, предшествующей инциденту (например, `backup_20261007_030000.csv`).
3. Найдите строку повреждённого объекта по `id` (первый столбец).
4. **Схема колонок Google Таблицы:**
   - Столбец 1: `id` (числовой идентификатор)
   - Столбец 2: `address` (адрес объекта)
   - Столбец 3: `total` (общая сумма сметы/договора)
   - Столбец 4: `paid` (внесённая оплата)
   - Столбец 5: `progress` (процент выполнения)
   - Столбец 6: `stage` (текущий этап)
   - Столбец 7: `photo` (ссылки на фотоотчёты)
   - Столбец 8: `token` (секретный токен доступа клиента к кабинету)
5. Вставьте восстановленную строку на место повреждённой в Google Таблице.
6. Проверьте корректность отображения объекта в боте (команда `/list` или просмотр объекта) и в клиентском кабинете.
