# Задачи проекта VoltGroup

**Что это.** Одна карточка = одна задача. Карточка самодостаточна: проблема, файлы, конкретные шаги, критерий готовности и способ проверки. Сессия агента = одна карточка, чтобы контекст не забивался смежными темами.

**Откуда взялось.** Карточки разбиты из [AUDIT.md](../AUDIT.md) — там исходный разбор и обоснование приоритетов.

**Как работать:**
1. Прочитать [AGENTS.md](../AGENTS.md) (правила) и [AGENT_STATE.md](../AGENT_STATE.md) (журнал и текущий фокус).
2. Взять **одну** карточку со статусом ⏳.
3. После завершения — отметить статус в карточке **и** записать результат в [AGENT_STATE.md](../AGENT_STATE.md) по шаблону из `AGENTS.md` §7.
4. Не считать задачу выполненной без вывода команды проверки из карточки.

> ⚠️ Номера строк в карточках — подсказка на момент аудита (ревизия `4884302`). После правок они сдвигаются: искать по названию функции, а не по номеру.

**Легенда:** ✅ выполнено · 🔄 в работе · ⏳ не начато · ⏸ приостановлено · 💬 требует решения человека

**Порядок внутри этапа:** `044` (снять задержку обхода — без этого остальное не работает) → `036` (sitemap и `Clean-param`) → `035` (дожать замеры: «Все страницы», статус sitemap, обход) → `045` (генератор отзывов — убирает ручную синхронизацию двух копий) → `039` + `038` (локальная выдача и доверие) → `041` + `042` (внешний контур) → `037` + `040` + `043` (контент, самый долгий).

**Про отзывы — план из двух шагов.** [045](045-reviews-generator.md) закрывает неудобство «править в двух местах»: источник правки остаётся один — `reviews.json`, HTML и микроразметка обновляются генератором. Отдельной будущей задачей идёт **забор отзывов из обсуждения ВКонтакте**: страница `vk.ru/topic-…` рендерится JavaScript, обычным HTTP-запросом содержимое не получить — нужен токен и метод API для комментариев обсуждений. Тогда цепочка замкнётся: `ВК → reviews.json → HTML`. **`reviews.json` удалять нельзя** — это точка стыковки.

**Ключевое правило этапа:** NAP (название, телефон, регион) должен совпадать **посимвольно** на сайте, в Яндекс.Бизнесе, Google Business, 2ГИС и всех каталогах. Расхождение ослабляет все источники сразу.

**Почему 046 первым.** Калькулятор — самый сильный актив сайта: 69 позиций с ценами, расчёт, четыре документа. Но в [static/js/estimate.js](../static/js/estimate.js) **нет ни одного обращения к API** — посчитав смету, посетитель не может отправить её мастеру и должен вручную перейти на главную и заполнить форму заново. Теряется человек, который уже вложил 10–20 минут и составил точное ТЗ.

**Порядок:** `046` (потеря лидов — самое дорогое) → `047` (печать договоров, которые отдают клиенту) → `048` (минуты работы) → `049` (полировка восприятия) → `050` (дизайн-система: правка всего CSS, требует визуальной проверки каждой страницы).

**Важно про 050:** это **не редизайн**. Палитра, шрифты и характер (dark-tech, неон, инженерная сетка) не меняются — приводятся к порядку только числовые значения. Критерий успеха: сайт выглядит так же, только ровнее. Полная смена дизайна рассмотрена и отклонена — обоснование в [AGENT_STATE.md](../AGENT_STATE.md), запись от 07.10.2026.

**Отложенные идеи, не оформленные карточками:** истории объектов «до/после» с цифрами (3–5 кейсов), видео работ, пакетные предложения «под ключ», запрос отзыва у клиента через бота в момент сдачи объекта, цели в Яндекс.Метрике на события калькулятора. Вернуться к ним, когда закроются 046–049.
