# Задача 008 — `.env.example` и защита секретов

**Пункт аудита:** № 33 (🟠 важно) · из [AUDIT.md](../AUDIT.md)
**Статус:** ⏳ не начато
**Файлы:** новый `.env.example`, `.gitignore`

## Проблема

Список обязательных переменных окружения существует только текстом в README. Файла-образца нет, поэтому при пересоздании сервиса конфигурация собирается по памяти. В [.gitignore](../.gitignore) отсутствует строка `.env` — при создании файла есть риск закоммитить секреты.

## Шаги

1. Создать `.env.example` с перечнем и пояснениями, **без значений**:
   - `BOT_TOKEN` — токен от @BotFather;
   - `CHAT_ID` — Telegram ID мастера, единственный разрешённый получатель;
   - `SHEET_URL` — ссылка на Google Таблицу;
   - `GOOGLE_CREDENTIALS` — JSON сервисного аккаунта одной строкой;
   - `TELEGRAM_SECRET_TOKEN` — секрет вебхука;
   - `ALLOWED_ORIGINS` — список через запятую (появляется в задаче 007).
2. Добавить в `.gitignore` строки `.env`, `.env.*` (кроме `.env.example`).
3. Указать для каждой переменной, что произойдёт при её отсутствии: например, без `BOT_TOKEN` бот не отправляет сообщения.
4. Сверить список с фактическим чтением в коде (`os.environ.get` в [server.py:68-71](../server.py#L68)).

## Критерий готовности

Новый разработчик поднимает бэкенд по `.env.example`, не задавая вопросов; `.env` не может попасть в коммит.

## Проверка

- `git check-ignore -v .env` → путь игнорируется.
- `git status --short` после создания `.env` → файла нет в списке.
- Каждая переменная из `.env.example` действительно читается кодом (сверка поиском по `os.environ`).
