# Задача 027 — Понятный отказ вместо ссылки на несуществующий объект

**Пункт аудита:** № 1, остаток (🔴 критично) · из [AUDIT.md](../AUDIT.md)
**Статус:** ✅ завершено (2026-10-06)
**Файлы:** `server.py`

## Проблема

В обработчике `o:link:<id>` при отсутствии объекта в таблице всё равно генерируется случайный токен:

```python
else:
    token = secrets.token_urlsafe(16)
```
([server.py:497-498](../server.py#L497))

Мастеру уходит ссылка на несуществующий объект. Такая ссылка гарантированно даст 403 («Неверный ключ доступа»), и мастер будет думать, что сломан кабинет, а не что объект не найден.

## Шаги

1. Если `cell` пустой — отправить сообщение «⚠️ Объект №X не найден в таблице» и прервать обработку (`return` внутри ветки или флаг).
2. Убрать генерацию токена в ветке `else`.
3. Заодно проверить `addr_text`: при отсутствии объекта он остаётся `по объекту №X` — при отказе это уже не используется.
4. Проверить, что при существующем объекте с **пустым** токеном поведение сохранилось: токен генерируется и **сохраняется** в колонку 8 ([server.py:494-496](../server.py#L494)).

## Критерий готовности

Ссылка выдаётся только для существующего объекта и всегда рабочая.

## Проверка

- `python -c "import ast; ast.parse(open('server.py',encoding='utf-8').read())"`.
- В Telegram открыть карточку объекта → «🔗 Ссылка клиенту» → приходит ссылка → открыть её в браузере → кабинет показывает данные (не 403).
- Проверить ветку отказа: удалить тестовый объект из таблицы, нажать кнопку из старого сообщения → приходит сообщение «не найден», ссылки нет.
- Для объекта с пустой колонкой 8: нажать ссылку → токен создан, записан в таблицу, ссылка работает.
