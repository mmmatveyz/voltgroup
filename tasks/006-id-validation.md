# Задача 006 — Валидация ID объекта и точный поиск

**Пункт аудита:** № 19 (🟠 важно) · из [AUDIT.md](../AUDIT.md)
**Статус:** ⏳ не начато
**Файлы:** `server.py`

## Проблема

`new_id = parts[0]` ([server.py:566](../server.py#L566)) принимает любую строку, а `ws.find()` ищет **вхождение подстроки**: `find("14")` может совпасть с ячейкой `145`. Мастер получит карточку чужого объекта или изменит не тот.

## Шаги

1. Проверять новый ID регуляркой `^\d{1,6}$`; иначе — сообщение об ошибке и возврат в меню ([server.py:567-580](../server.py#L567)).
2. Заменить все `ws.find(str(obj_id), in_column=1)` на поиск с последующей проверкой точного равенства `str(row[0]).strip() == obj_id`. Затронутые места: [server.py:210](../server.py#L210), [341](../server.py#L341), [444](../server.py#L444), [464](../server.py#L464), [484](../server.py#L484), [543](../server.py#L543), [607](../server.py#L607).
3. Проверять `progress` из callback как целое в диапазоне 0-100 ([server.py:440](../server.py#L440)).
4. Проверять `idx` этапа перед обращением к `STAGES` — там же устранить `stage_name` вне области видимости ([server.py:458-468](../server.py#L458)).

## Критерий готовности

Объект `14` и объект `145` не путаются; некорректный ID отклоняется с сообщением.

## Проверка

- `python -c "import ast; ast.parse(open('server.py',encoding='utf-8').read())"`.
- В таблице создать тестовые объекты `14` и `145` → нажать кнопку объекта `14` → открывается именно `14`.
- `m:new` → отправить `14а` → отказ, объект не создан.
- `m:new` → отправить `14` (существующий) → сообщение «уже существует».
