# Задача 047 — Печатные стили `@media print`

**Направление:** UX / деловые документы · добавлена после аудита (07.10.2026)
**Статус:** ✅ завершено (09.10.2026)
**Файлы:** `static/js/documents.js` (встроенные стили 4 документов), `tools/test_doc_smoke.js`

## Проблема

В проекте **ноль блоков `@media print`** — проверено в [static/css/style.css](../static/css/style.css). При этом печать — основной способ получить четыре юридических документа: смету, КП, акт и договор. Люди печатают их и подписывают.

Что видит пользователь сейчас:

- колонтитулы браузера с адресом `blob:` и датой в углах листа;
- поля страницы по умолчанию, из-за чего содержимое прижимается к краям;
- **шапка таблицы не повторяется на второй странице** — а смета на 69 позиций занимает 2-3 листа, и вторая страница выглядит как набор чисел без заголовков колонок;
- строка таблицы может разорваться пополам между страницами;
- при печати самой страницы калькулятора (Ctrl+P на `/estimate.html`) в лист попадают шапка сайта, меню, кнопки и футер.

## Важно: две разные области печати

Документы генерируются в **новом окне через Blob-URL** ([static/js/documents.js:182](../static/js/documents.js#L182), функция `openPrintWindow`) и содержат **свой встроенный `<style>`** ([static/js/documents.js:237](../static/js/documents.js#L237) и далее для каждого документа). Стили основной страницы на них **не действуют**. Поэтому правки нужны в двух местах:

| Область | Что делать | Зачем |
|---|---|---|
| **Встроенные стили документов** в `documents.js` | Добавить print-правила внутрь каждого из 4 шаблонов | Это то, что реально печатают и подписывают |
| **`static/css/style.css`** | Добавить один блок `@media print` | Чтобы Ctrl+P на страницах сайта не печатал меню, кнопки и футер |

## Шаги

### 1. Print-правила в шаблонах документов

В каждый из четырёх шаблонов в `documents.js` (смета, КП, акт, договор) добавить:

```css
@page { size: A4; margin: 15mm; }

@media print {
    body { margin: 0; padding: 0; }
    /* Шапка таблицы повторяется на каждой странице */
    thead { display: table-header-group; }
    tfoot { display: table-footer-group; }
    /* Строка не разрывается между страницами */
    tr, .total-line, .total-row { break-inside: avoid; page-break-inside: avoid; }
    /* Блоки подписей и итогов не отрываются от содержимого */
    .signatures, .final-price, .grand-total { break-inside: avoid; page-break-inside: avoid; }
    /* Принудительный разрыв перед приложением (у договора) */
    .page-break { break-before: page; page-break-before: always; }
    /* Кнопки печати и закрытия в лист не попадают */
    .btn, .no-print, button { display: none !important; }
    /* Фон итоговых строк сохранить — иначе в некоторых браузерах он пропадёт */
    .total-line, .grand-total, .final-price { -webkit-print-color-adjust: exact; print-color-adjust: exact; }
}
```

Проверить, что селекторы существуют в текущих шаблонах: `.total-line`, `.total-row`, `.grand-total`, `.final-price`, `.signatures`, `.page-break`. Если названия отличаются — использовать фактические, а не из этого примера.

**У договора** в шаблоне уже есть разрыв перед приложением — проверить, что он работает как `page-break-before`, а не как обычный отступ (сейчас это `style="page-break-before: always; margin-top: 30px"` — работает, но лучше вынести в класс).

### 2. Print-блок для страниц сайта

В [static/css/style.css](../static/css/style.css) добавить в конец файла:

```css
@media print {
    /* Скрыть интерфейс, который не имеет смысла на бумаге */
    .site-header, .nav-links, .mobile-toggle, .mobile-menu-overlay,
    .footer, .floating-rating, .btn, .no-print, .breadcrumbs { display: none !important; }

    body { background: #fff !important; color: #000 !important; }
    a { color: #000 !important; text-decoration: none; }

    /* Прайс на бумаге: таблица не должна разрываться по строкам */
    .price-table thead { display: table-header-group; }
    .price-table tr { break-inside: avoid; page-break-inside: avoid; }
    /* Аккордеоны раскрыть: иначе при печати видно только заголовки категорий */
    details.price-accordion { open: true; }
    details.price-accordion > .price-accordion-body { display: block !important; }
}
```

⚠️ **Про аккордеоны прайса.** Прайс построен на `<details>` — закрытые категории при печати не раскроются. CSS-свойство `open` не управляется стилями, поэтому только CSS-ом раскрыть не получится. Проверить фактическое поведение: если закрытые категории не печатаются, потребуется небольшая JS-правка — перед печатью раскрывать все `details` (обработчик `window.onbeforeprint`), после печати возвращать исходное состояние. Это же решает и существующие кнопки «Развернуть все» / «Свернуть все».

### 3. Проверить, что `.no-print` не конфликтует

В шаблонах документов уже есть элементы с классом `.btn.btn-close` («Закрыть») и кнопки печати. Убедиться, что они не попадают в лист. Если у них нет общего класса — добавить `no-print` в разметку шаблонов.

## Критерий готовности

Печать любого из четырёх документов даёт опрятный лист А4: без интерфейса и колонтитулов, с полями, с повторяющейся шапкой таблицы на каждой странице и без разорванных строк. Ctrl+P на страницах сайта печатает только содержание.

## Проверка

1. `python tools/check.py` → без ошибок.
2. Открыть `/estimate.html`, собрать смету на **более 20 позиций** (чтобы гарантированно было 2+ страницы), сгенерировать смету → кнопка печати → **в режиме предпросмотра** проверить:
   - поля страницы есть, содержимое не прижато к краям;
   - шапка таблицы («№ | Наименование | Ед. | Кол-во | Цена | Сумма») присутствует на второй и последующих страницах;
   - ни одна строка не разорвана между страницами;
   - блок подписей целиком на одной странице;
   - кнопки «Печать» и «Закрыть» в лист не попали.
3. То же для КП, акта и договора (у договора — проверить, что приложение начинается с новой страницы).
4. Ctrl+P на `/install/` и `/estimate.html` → в предпросмотре нет шапки сайта, меню, кнопок и футера.
5. Проверить в **Chrome и в Яндекс.Браузере** (движки разные, `break-inside` поддерживается обоими, но проверить стоит).
6. Сохранить в PDF через диалог печати → файл открывается, текст не разъехался.

## Что НЕ делать

- Не менять содержимое и формулировки документов — только печатное оформление.
- Не трогать экранные стили: правки только внутри `@media print`.
- Не добавлять внешние CSS-файлы в генерируемые документы: они открываются как Blob-URL и должны оставаться автономными.
