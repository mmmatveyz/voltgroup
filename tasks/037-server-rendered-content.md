# Задача 037 — Прайс и галерея: контент должен быть в HTML

**Направление:** SEO · техническая часть · из [AUDIT.md](../AUDIT.md) (пункт № 7 и SEO-раздел)
**Статус:** ⏸ отложено по решению заказчика — **необходимость подтверждена, правку пока не делаем**
**Файлы:** `install/index.html`, `engineering/index.html`, `index.html`, `works.html`, `static/data/prices.json`, `gallery/gallery-config.json`

## ✅ Проверка проведена 07.10.2026: цены в отрендеренном HTML ОТСУТСТВУЮТ

Заказчик проверил `https://voltgroup-spb.ru/install/` через **Яндекс.Вебмастер → Инструменты → Проверка страницы** (инструмент показывает HTML после исполнения JS).

То есть опасение из аудита подтвердилось фактом: коммерческий контент — наименования работ и цены — в индекс Яндекса не попадает. Это уже не гипотеза, а измеренный дефект.

**Решение заказчика (07.10.2026): пока не менять.** Правка отложена осознанно, дефект зафиксирован в этом документе, чтобы к вопросу не возвращались заново.

**Что это значит по приоритету:** дефект не блокирующий (сайт работает, заявки идут, страницы индексируются), но он напрямую бьёт по коммерческим запросам вида «сборка электрощита спб цена» — по ним страница не имеет шансов, потому что в индексе нет ни цен, ни названий работ.

**Когда возвращаться:** когда появится время на контентную работу или если в Вебмастере по разделам не будет показов по коммерческим запросам. Технически правка дешёвая — см. «План работ» ниже; образец реализации уже есть в задаче [045](045-reviews-generator.md) (генератор отзывов работает по тому же принципу).

## План работ, если разморозят

Шаблон уже отработан на отзывах в [045](045-reviews-generator.md) — здесь делается аналогично:

1. `tools/build_prices.py` по образцу `tools/build_reviews.py`: читает `static/data/prices.json`, генерирует разметку аккордеонов (`<details>`/`<summary>`, классы `price-accordion`, `price-table`) и вставляет **между маркерами** `<!-- prices:install:begin -->` … `<!-- prices:install:end -->` (и то же для `engineering`).
2. Режим `--check`: сравнить сгенерированное с файлом, вернуть код 1 при расхождении — подключается в `tools/check.py`, как сделано для отзывов.
3. Убрать дублирующий JS-рендер прайса из `install/index.html` и `engineering/index.html` (контейнеры заполняются генератором).
4. После правки `prices.json` — обязательный запуск генератора; зафиксировать правило в [AGENTS.md](../AGENTS.md) §2.1.
5. Проверка: локальный сервер с выключенным JS — прайс виден; Вебмастер → Проверка страницы → цены в отрендеренном HTML есть.

## ⏸ Исходное обоснование отсрочки (06.10.2026, до проверки)

Решение было принято 06.10.2026: правку не делать, пока не подтверждено, что она нужна. Проверка требовалась через **Яндекс.Вебмастер → Инструменты → Проверка страницы** (`https://voltgroup-spb.ru/install/`).

- **Цены есть** → правка не нужна, пункт закрывается.
- **Цен нет** → возвращаемся к карточке. **Этот случай и подтвердился 07.10.2026.**

Логика отсрочки была такой: JS на страницах элементом прост (один `fetch` локального файла и вставка строк), такое роботы часто обрабатывают надёжно — поэтому сначала замер, потом работа.

## Контекст: GitHub Pages не умеет серверную генерацию

Уточнено 06.10.2026: сайт опубликован классическим способом — содержимое ветки `main` как есть (`.github/workflows/` нет, `_config.yml` нет, `.nojekyll` нет, `CNAME` = `voltgroup-spb.ru`). **Pages не выполняет код при отдаче страницы** — аналога `buildCommand` там нет. Поэтому «генерировать прайс при выкладке» возможно только двумя способами:

| Вариант | Как | Цена |
|---|---|---|
| **(а) Генерация + коммит** (рекомендуемый) | Локально `python tools/build.py` → скрипт обновляет HTML → коммит. Pages отдаёт готовое | Ноль инфраструктуры; нужно помнить про запуск после правки цен |
| **(б) GitHub Actions** | Workflow при пуше запускает скрипт и публикует артефакт | Полная автоматика; добавляется workflow и меняется модель публикации Pages |

## Техническая основа: конфликтов с текущим кодом нет

Проверено в коде: контейнеры `#install-prices` и `#eng-prices` в разметке **пустые**, JS строит аккордеоны из `fetch('../static/data/prices.json')` ([install/index.html:493](../install/index.html#L493)). Ключевая строка — [install/index.html:501](../install/index.html#L501):

```javascript
container.textContent = ''; // Безопасная очистка
```

JS **очищает контейнер перед рендером**, поэтому статичная разметка внутри безопасна: робот и человек без JS видят HTML из файла, после загрузки JS контент заменяется тем же самым, дублей не возникает. Объём: `install` — 69 позиций, `engineering` — 8.

⚠️ Оговорка про Jekyll: Pages прогоняет файлы через Jekyll (`.nojekyll` отсутствует). Практического риска нет, но если в названии работы когда-нибудь появится текст вида `{{ … }}`, Pages обработает его как шаблон. Учитывать при генерации.

## Если пункт разморозят — план работ

1. `tools/build.py`: читает `static/data/prices.json`, генерирует разметку аккордеонов (структура `details/summary`, классы, иконки категорий, склонения «позиция/позиции/позиций» — как в JS) и вставляет **между маркерами** `<!-- prices:install:begin -->` … `<!-- prices:install:end -->`, не задевая остальную разметку.
2. Режим `--check`: сравнить сгенерированное с содержимым файлов, вернуть ошибку при расхождении — защита от «цены поменяли, страницы не перегенерировали».
3. Правило в [AGENTS.md](../AGENTS.md) §2.1: после правки `prices.json` обязателен запуск `tools/build.py`.
4. Проверка: локальный сервер с выключенным JS — прайс виден.
5. Второй аспект карточки (вес галереи) ведётся отдельно в [010](010-gallery-weight.md) и от этой паузы не зависит.

## Проблема (исходная формулировка)

Ключевой коммерческий контент подгружается скриптом после загрузки страницы:

- прайс-листы разделов — `fetch('./static/data/prices.json')`;
- галерея работ — `fetch('./gallery/gallery-config.json')` ([works.html:452](../works.html#L452), [index.html:917](../index.html#L917)).

Поисковые роботы исполняют JS нестабильно: у Яндекса и Google это отдельная очередь рендеринга с задержкой, а часть блоков может не попасть в индекс вообще. Итог: **тексты с ценами и названиями работ, то есть самый ценный для SEO контент, могут отсутствовать в индексе**. Для коммерческих запросов вида «сборка электрощита спб цена» это прямая потеря.

Второй аспект — вес: 13,5 MB картинок галереи, отдаваемых через `background-image`, вредят Core Web Vitals, а они влияют на ранжирование.

## Шаги

1. **Отдавать прайс в HTML.** Варианты по возрастанию усилий:
   - при выкладке генерировать статический HTML из `prices.json` (скрипт сборки/выкладки);
   - либо отдавать `<noscript>`-версию прайса со всеми позициями;
   - либо рендерить прайс серверной частью (сейчас `server.py` занят ботом — не смешивать).
2. **Галерею перевести на `<img loading="lazy">` со `srcset`** вместо `background-image` (совпадает с задачей 010 из аудита).
3. Проверить, что в HTML попадают: названия работ, единицы измерения, цены — то есть текст, по которому ищут.
4. Не ломать текущую интерактивность: фильтры, поиск, «только выбранные», калькулятор продолжают работать.
5. Убедиться, что страница корректно выглядит **с выключенным JS** — это и есть проверка индексируемости.

## Критерий готовности

Названия работ и цены присутствуют в исходном HTML страницы (видны через «Просмотр кода страницы», а не только в DOM после исполнения JS).

## Проверка

- `curl -s https://voltgroup-spb.ru/install/ | findstr "Штробление"` → название работы найдено в исходном HTML.
- Отключить JS в браузере (DevTools → Settings → Debugger → Disable JavaScript) → открыть раздел: прайс виден.
- Яндекс.Вебмастер → «Индексирование» → проверка страницы как робот (инструмент «Проверить страницу») → в отрендеренном виде есть цены.
- Проверить Core Web Vitals после перевода галереи на `<img>`: LCP и общий вес страницы.
