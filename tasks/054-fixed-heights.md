# Задача 054 — Проход 6 задачи 050: заменить фиксированные высоты на `aspect-ratio`/`min-height`

**Направление:** дизайн-система · Проход 6 [tasks/050](050-design-system.md), вынесен в отдельную карточку
**Статус:** ⏳ не начато
**Файлы:** `static/css/style.css`

## Что не так: замер

- `height: <N>px` — **29 вхождений, 19 уникальных значений**: `1, 2, 8, 14, 16, 24, 28, 32, 34, 38, 40, 44, 48, 68, 76, 80, 104, 220, 380`.
- `aspect-ratio` — **0 вхождений**.
- `min-height` в px — 3 вхождения (`36px`, `42px`, `110px`) плюс `100vh` и `unset`.

**Почему это не косметика.** Жёсткая высота ломается, когда контент становится выше расчётного: при системном масштабе шрифта 125 %, при длинном тексте (адрес, название работ в прайсе) и при переводе страницы. Часть посетителей видит обрезанный или наложенный текст. Отдельно учесть скелетоны: `380px` у `.skeleton-card` ([works.html](../works.html)) и `68px` у `.skeleton-row` (`install/`, `engineering/`, обе районные страницы) подобраны под фактический размер контента — при замене не должно появиться скачков вёрстки (layout shift). Автотестами эти классы не покрыты, проверка ручная.

## Шаги

1. Выписать каждое из 29 вхождений с селектором и назначением: медиа-контейнер (изображение, карта, видео), карточка со текстом, декоративный элемент.
2. Для медиа-контейнеров — `aspect-ratio` (например, `aspect-ratio: 4 / 3`) вместо `height`.
3. Для текстовых блоков — `min-height` вместо `height`.
4. Декоративные элементы (точки, разделители, иконки фиксированного размера) — оставить, они входят в допустимые ≤ 5.
5. Проверять каждый блок при **масштабе 125 %** и с удлинённым текстом (вставленным вручную в DevTools).
6. Кэш-бэстинг: синхронно поднять `?v=` на всех 12 страницах.

## Критерий готовности

| Показатель | Цель |
|---|---|
| Фиксированных `height` в px | ≤ 5 (только декор) |
| `aspect-ratio` для медиа | используется там, где раньше была высота |
| Масштаб 125 % и длинный текст | вёрстка не ломается ни на одной странице |
| Внешний вид на 100 % | не изменился на 1440 / 1024 / 768 / 390 px |

## Проверка

1. Замер до/после:
   ```powershell
   $css = Get-Content static/css/style.css -Raw
   [regex]::Matches($css,'(?<![\w-])height:\s*\d+(?:\.\d+)?px').Count
   [regex]::Matches($css,'(?<![\w-])height:\s*(\d+(?:\.\d+)?)px') | % { $_.Groups[1].Value } | Sort-Object -Unique
   [regex]::Matches($css,'aspect-ratio:').Count
   ```
2. `python tools/check.py` → без новых ошибок.
3. Визуальная проверка с системным масштабом 125 % (браузер → масштаб 125 %) на всех страницах: главная, `/install/`, `/engineering/`, `/contacts/`, `works.html`, `estimate.html`, юридические, `client/index.html`, обе районные.
4. Проверить скелетоны `works.html` и прайс-аккордеоны `install/`/`engineering/`: у них высоты заданы под фактический размер элементов, при замене не должно появиться скачков вёрстки (layout shift).

## Что НЕ делать

- Не менять дизайн и размеры «на глаз»: задача — устойчивость, а не новый вид.
- Не трогать логику JS и разметку, кроме случаев, когда высота задана инлайном (это [задача 052](052-inline-styles.md)).
- Не заменять высоты у декоративных элементов ради формального выполнения критерия.
