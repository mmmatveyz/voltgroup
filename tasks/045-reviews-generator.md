# Задача 045 — Генератор статичного блока отзывов из `reviews.json`

**Направление:** SEO + удобство сопровождения · добавлена после аудита (07.10.2026)
**Статус:** ✅ завершено (07.10.2026)
**Файлы:** новый `tools/build_reviews.py`, `index.html`, `tools/check.py`
**Связанные:** [038](038-reviews.md) (блок отзывов уже свёрстан), [037](037-server-rendered-content.md) (тот же приём для прайса)

## Зачем

Сейчас отзывы живут в двух местах, и при добавлении отзыва нужно править оба:

1. [static/data/reviews.json](../static/data/reviews.json) — данные;
2. [index.html](../index.html) — статичный HTML-блок ([index.html:776](../index.html#L776)) **и** микроразметка `AggregateRating` в `<head>` ([index.html:113](../index.html#L113)).

Плюс третий механизм: скрипт на странице ([index.html:1130](../index.html#L1130)) очищает контейнер и перерисовывает те же карточки из JSON — это ~86 строк кода, который дублирует уже свёрстанную разметку.

**Цель задачи:** источник правки один — `reviews.json`. HTML-блок и микроразметка обновляются командой.

**Важно:** `reviews.json` остаётся как формат-посредник намеренно. В планах заказчика — автоматически подтягивать отзывы из обсуждения ВКонтакте (`vk.ru/topic-237900859_57977759`); тогда JSON станет точкой стыковки, а генератор — вторым звеном цепочки `ВК → JSON → HTML`. Поэтому **JSON и генератор не удалять и не заменять на «только статика»**.

## Шаги

### 1. Разметить генерируемую область в `index.html`

Обернуть блок карточек маркерами, чтобы скрипт правил только эту часть файла:

```html
<!-- reviews:begin (генерируется tools/build_reviews.py из static/data/reviews.json) -->
<article class="review-card fade-in"> ... </article>
...
<!-- reviews:end -->
```

Маркеры ставить внутри `<div class="reviews-grid" id="reviewsGrid">` ([index.html:775](../index.html#L775)). Разметку каждой карточки взять **побайтово как в текущем файле**: классы `review-card`, `review-card-header`, `review-author-wrap`, `review-avatar-char`, `review-author-name`, `review-object-type`, `review-badge vk|ya`, `review-stars`, `review-text`, `review-footer`. Ничего не менять в структуре и отступах.

### 2. Написать `tools/build_reviews.py`

По образцу стиля `tools/check.py`: UTF-8 вывод, `ROOT_DIR = Path(__file__).resolve().parent.parent`, понятные сообщения на русском, ненулевой код возврата при ошибке.

Логика:

1. Читает `static/data/reviews.json` (массив объектов, поля: `id`, `author`, `avatar`, `service`, `source`, `sourceLabel`, `sourceUrl`, `rating`, `text`, `date`, `status`).
2. Генерирует HTML всех карточек в том же виде, что сейчас в файле:
   - аватар — `item.avatar` или первая буква имени;
   - бейдж источника — класс `ya` если `source` в (`yandex`, `ya`), иначе `vk`; текст из `sourceLabel`;
   - звёзды — `★`, повторённые `rating` раз, с `aria-label="Оценка: N из 5"`;
   - подвал — `status` и `Оценка {rating}.0`.
   - **Экранирование обязательно:** текст отзыва может содержать `<`, `&`, кавычки. Использовать `html.escape`. Отзывы приходят от людей — это защита от XSS и от поломки вёрстки.
3. Заменяет содержимое между маркерами `reviews:begin` / `reviews:end`.
4. Пересчитывает и обновляет в микроразметке JSON-LD:
   - `reviewCount` → число отзывов;
   - `ratingValue` → средняя оценка (округление до одного знака);
   - список `"review": [...]` — по одному объекту `Review` на отзыв с `author.name`, `reviewRating.ratingValue`, `reviewBody`.
5. Режимы запуска:
   - без аргументов — записать изменения;
   - `--check` — только сравнить, ничего не писать; при расхождении вернуть код 1 и напечатать, что именно отличается. Этот режим будет вызывать `tools/check.py`.
6. Идемпотентность: повторный запуск не должен менять файл. Проверить это явно (см. «Проверка»).

### 3. Убрать дублирующий рендер со страницы

Удалить блок динамической перерисовки отзывов ([index.html:1130–1215](../index.html#L1130)) — он больше не нужен, разметка приходит из HTML. Убедиться, что после удаления:

- карточки отображаются (они в HTML);
- `reviews.json` больше не запрашивается со страницы;
- ничего не сломалось в анимациях: карточки имеют класс `fade-in`, а наблюдение за ними настраивается отдельно — проверить, что отзывы становятся видимыми, а не остаются прозрачными. Если анимация зависит от удалённого кода, оставить минимальную часть или добавить `visible` прямо в разметку, как это делает `IntersectionObserver` для остальных блоков.

### 4. Обновить `tools/check.py`

Заменить содержимое `check_reviews_sync()` ([tools/check.py:875](../tools/check.py#L875)) на вызов внешней проверки:

```python
subprocess.run([sys.executable, str(ROOT_DIR / "tools" / "build_reviews.py"), "--check"], ...)
```

Плюс оставить проверки, которые не зависят от генератора: наличие обязательных полей в JSON, непустой список, соответствие `reviewCount`/`ratingValue` фактическим данным. То есть `check.py` больше не сравнивает HTML с JSON сам — это делает генератор в режиме `--check`, а `check.py` сообщает результат.

### 5. Заодно поправить нумерацию разделов в `check.py`

В файле сбита нумерация: `[1/8]`…`[7/8]`, затем `[8/9]`, `[9/10]`, `[10/11]`, потом снова `[11/11]` и `[12/12]`, а новая секция отзывов помечена `[13/13]`. Фактически секций 13. Привести все подписи к виду `[N/13]` — это чисто косметика вывода, но сейчас она путает.

## Критерий готовности

- Добавление отзыва требует правки **только** `static/data/reviews.json`, после чего одна команда обновляет HTML и микроразметку.
- `python tools/build_reviews.py --check` возвращает 0, когда файлы синхронны, и 1 с понятным сообщением, когда нет.
- В `index.html` нет кода перерисовки отзывов из JSON.
- `python tools/check.py` проходит и включает проверку синхронности отзывов.

## Проверка

1. `python -c "import ast; ast.parse(open('tools/build_reviews.py',encoding='utf-8').read())"` → без ошибок.
2. `python tools/build_reviews.py` на текущих данных → файл не изменился (`git diff -- index.html` пуст). Это подтверждает, что генератор воспроизводит существующую разметку, а не свою.
3. **Идемпотентность:** запустить генератор дважды подряд → после второго запуска `git diff` пуст.
4. **Негативный тест:** добавить в `reviews.json` четвёртый отзыв-копию с другим именем → запустить генератор → в HTML появилась четвёртая карточка, `reviewCount` стал 4. Затем `git checkout -- static/data/reviews.json index.html` и проверить, что вернулось исходное состояние.
5. **Тест `--check`:** вручную испортить имя автора в HTML → `python tools/build_reviews.py --check` → код 1 и сообщение о расхождении. `python tools/check.py` → тоже код 1.
6. `node tools/test_doc_smoke.js` и остальные наборы → без изменений.
7. Открыть `index.html` через `tools/serve.cmd` → блок отзывов виден, карточки не прозрачные, звёзды и бейджи на месте.
8. Отключить JavaScript в браузере → отзывы по-прежнему видны (главный смысл статичного блока).

## Что НЕ делать

- Не удалять `static/data/reviews.json` — это точка стыковки для будущей интеграции с ВК.
- Не менять тексты отзывов, имена, порядок и дизайн карточек.
- Не трогать разметку `LocalBusiness`/`FAQPage` — правится только `aggregateRating` и массив `review`.
- Не добавлять сборочный шаг в GitHub Actions: генератор запускается локально перед коммитом, как и обсуждалось для прайса в [037](037-server-rendered-content.md).

## Следующий шаг после этой задачи

Отдельной карточкой — забор отзывов из обсуждения ВКонтакте через API (метод для комментариев обсуждений) с проверкой доступов: страница `vk.ru/topic-…` рендерится JavaScript, обычным HTTP-запросом содержимое не получить, нужен токен. Тогда цепочка замкнётся: `ВК → reviews.json → HTML`.
