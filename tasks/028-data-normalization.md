# Задача 028 — Нормализация данных из таблицы

**Пункт аудита:** № 27 · из [AUDIT.md](../AUDIT.md)
**Статус:** ✅ завершено (07.10.2026)
**Файлы:** `server.py`, `client/index.html`, `tools/check.py`

## Проблема

Данные из таблицы отдаются клиенту как есть. `progress` попадает в `parseInt` без проверки диапазона ([client/index.html:321](../client/index.html#L321)) — при значении `150`, `-5` или тексте прогресс-бар и таймлайн ведут себя непредсказуемо ([client/index.html:381-391](../client/index.html#L381)). Суммы передаются строками произвольного формата. Сейчас это безопасно лишь потому, что мастер вводит данные через бота, но таблицу можно править руками.

## Шаги

1. В `get_status` нормализовать ответ:
   - `progress` → целое, зажатое в 0-100 (`max(0, min(100, int(...)))`, с обработкой нечисловых значений как 0);
   - `total`, `paid` → привести к числу или оставить строкой, но в предсказуемом виде;
   - `stage` → если значение не из списка `STAGES`, отдать как есть, но залогировать расхождение;
   - `photo` → разобрать список, отбросить пустые элементы и дубликаты.
2. В `build_object_view` применять ту же нормализацию, чтобы карточка в боте и кабинет показывали одинаковое.
3. На клиенте добавить защиту от `NaN`: если `parseInt` не дал числа, показывать 0 и не ломать таймлайн.
4. Не скрывать проблему: при некорректном значении писать в лог, чтобы мастер узнал о ручной правке, ломающей формат.

## Критерий готовности

Некорректные значения в таблице не ломают интерфейс; в логах есть запись о проблемной ячейке.

## Проверка

- В тестовой строке выставить `progress = 150` → в кабинете бар ограничен 100%, таймлайн в разумном состоянии, в логах предупреждение.
- Выставить `progress = "много"` → кабинет показывает 0%, ошибок в консоли нет.
- Выставить `paid = "50 000 ₽"` → кабинет показывает сумму корректно, без «NaN».
- В колонке фото указать `url1,,url2, url2` → отображаются две картинки без дублей.
