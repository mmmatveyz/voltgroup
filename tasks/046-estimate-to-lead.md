# Задача 046 — Передать смету мастеру из калькулятора

**Направление:** конверсия · добавлена после аудита (07.10.2026)
**Статус:** ✅ завершено (08.10.2026)
**Файлы:** `estimate.html`, `static/js/estimate.js`, `server.py`, `tools/test_estimate_calc.js`
**Приоритет:** самый высокий из «постаудитных» — закрывает разрыв в воронке

## Проблема

Калькулятор считает смету и позволяет выгрузить её в PDF, Excel и буфер обмена, но **не позволяет отправить мастеру**. Проверено: в [static/js/estimate.js](../static/js/estimate.js) единственный `fetch` — загрузка `prices.json` ([стати строки 69](../static/js/estimate.js#L69)); обращений к API бэкенда нет.

Что происходит с посетителем: он выбирает 30-40 позиций, видит «ИТОГО 187 400 ₽», скачивает PDF — и дальше должен **сам** догадаться перейти на главную, найти форму и ввести данные заново. Практически никто так не делает.

**Цена потери максимальная из возможных:** человек уже вложил 10-20 минут, составил точное ТЗ с объёмами работ — и уходит на последнем шаге.

## Важно: это не SEO, а конверсия

Отдельно от [037](037-server-rendered-content.md) (прайс в HTML для индексации). Здесь цель — не потерять того, кто уже посчитал. Правка не пересекается с 037 и не зависит от решения по ней.

## Шаги

### 1. Поля для контактов в калькуляторе

Сейчас в блоке данных заказчика есть только ([estimate.html:340-343](../estimate.html#L340)):
- `#client-name` — имя
- `#client-address` — адрес объекта
- `#estimate-date` — дата
- `#invoice-number` — № сметы

**Телефона нет.** Добавить поле в том же стиле (`class="form-group"` + `form-label` + `form-input`):

```html
<div class="form-group">
    <label class="form-label" for="client-phone">Телефон для связи</label>
    <input type="tel" id="client-phone" class="form-input" placeholder="+7 (___) ___-__-__" autocomplete="tel">
</div>
```

Телефон в список работ и в документы **не добавлять** — он нужен только для передачи заявки. Если решите выводить его в договоре, это отдельная правка.

### 2. Кнопка «Передать смету мастеру»

Разместить рядом с существующими кнопками действий ([estimate.html:435-449](../estimate.html#L435), блок с «Копировать», «Скачать PDF», «Документы»): основная кнопка `btn btn-primary`, визуально заметнее остальных.

### 3. Формирование текста заявки

Использовать готовые функции из [static/js/estimate.js](../static/js/estimate.js): `calculateTotals()`, `getFormData()`, `buildCsvData()` / существующий сборщик текста для мессенджеров.

Текст для отправки — компактный, читаемый в Telegram:

```
⚡ Заявка из калькулятора
👤 Имя: <client-name>
📞 Телефон: <client-phone>
📍 Адрес: <client-address>

Работы (12 позиций):
1. Штробление бетона — 40 м.п. × 700 ₽ = 28 000 ₽
...
Материалы: 34 500 ₽ (закупка мастером)
Скидка: 5% (−8 200 ₽)
ИТОГО: 187 400 ₽

Ссылка на расчёт: <опционально>
```

Ограничения, которые надо учесть:
- **Обрезка.** У Telegram лимит 4096 символов на сообщение. Смета на 69 позиций столько не даст — поэтому: если позиций больше 15, перечислять первые 15 и добавлять «…и ещё N позиций». Итоговые суммы выводить всегда.
- **Экранирование.** Текст уходит в Telegram с `parse_mode=HTML`, а сервер применяет `html.escape` к полям. Значит специальные символы не сломают разметку — но не собирать HTML конкатенацией на клиенте, отправлять чистый текст.
- **Пустая смета.** Если `grandTotal === 0` или позиций нет — кнопку блокировать или показывать сообщение «Сначала добавьте работы в смету».

### 4. Отправка

Эндпоинт уже есть и принимает нужные поля ([server.py](../server.py), маршрут `/send-message`, лимит `5 per minute`):

```javascript
const apiUrl = (window.VG_API || '');
fetch(`${apiUrl}/send-message`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ name, phone, service: summaryText, source: 'calculator' })
});
```

Требования:
- `apiUrl` брать из `window.VG_API` ([static/js/config.js](../static/js/config.js)) — адрес API в коде не дублировать.
- **`AbortController` с таймаутом 15 секунд.** Бэкенд на бесплатном тарифе Render засыпает; без таймаута кнопка «зависнет» на 30-60 секунд. Это та же проблема, что решалась в [tasks/009](009-form-timeout.md) для формы на главной — взять решение оттуда.
- Проверять телефон на 11 цифр, как в форме на главной ([index.html](../index.html), обработчик `leadForm`).
- Обрабатывать `429` отдельным текстом, а не общей ошибкой.
- При успехе показать подтверждение и **предложить резервный канал**: ссылку на Telegram (данные в `window.VG_COMPANY.telegram`). Сообщение об ошибке тоже должно давать эту ссылку, а не просто «попробуйте позже».
- После успешной отправки — не сбрасывать смету, человек может захотеть её сохранить.

### 5. Проверить, нужно ли трогать `server.py`

Скорее всего нет: `/send-message` принимает `name`, `phone`, `service`, `source` и формирует сообщение в Telegram. Убедиться, что длинный `service` не ломает уведомление и не превышает лимиты Telegram. Если в `server.py` есть обрезка — проверить её поведение на длинном тексте. При необходимости добавить в уведомление пометку «из калькулятора» (поле `source` для этого и есть).

## Критерий готовности

Посетитель может посчитать смету и отправить её мастеру одной кнопкой, не покидая страницу. Заявка приходит в Telegram с составом работ, суммами и контактом.

## Проверка

1. `python tools/check.py` → без ошибок.
2. Локально через `tools/serve.cmd`: открыть `/estimate.html`, добавить 3-4 позиции, заполнить имя и телефон, нажать «Передать смету мастеру» → в Telegram приходит сообщение с составом и итогом.
3. **Негативные сценарии:**
   - пустая смета → кнопка не отправляет, показывается понятное сообщение;
   - телефон из 5 цифр → отказ с подсказкой формата;
   - отключить сеть в DevTools → появляется сообщение об ошибке со ссылкой на Telegram, кнопка снова активна.
4. **Таймаут:** Network → Custom 30 секунд задержки ответа → через 15 секунд показывается сообщение, а не бесконечное ожидание.
5. **Длинная смета:** выбрать более 15 позиций → в сообщении 15 строк и пометка «и ещё N», итоговые суммы на месте.
6. Отключить JavaScript → кнопка не мешает остальному интерфейсу (калькулятор и так требует JS).

## Что НЕ делать

- Не менять существующие кнопки (PDF, Excel, копирование) и не ломать их.
- Не добавлять телефон заказчика в генерируемые документы без отдельного решения.
- Не хардкодить адрес API — только `window.VG_API`.
- Не дублировать логику подсчёта: использовать существующие функции калькулятора.
