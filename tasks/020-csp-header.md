# Задача 020 — CSP через HTTP-заголовок

**Пункт аудита:** № 13 · из [AUDIT.md](../AUDIT.md)
**Статус:** ✅ завершено (07.10.2026)
**Файлы:** конфигурация хостинга (`.htaccess` или nginx), все HTML-страницы, `server.py`

## Проблема

CSP задан только через `<meta http-equiv>` на каждой странице отдельно ([index.html:13](../index.html#L13), [estimate.html:7](../estimate.html#L7) и далее). Это слабее заголовка: не покрывает не-HTML ответы, не поддерживает `frame-ancestors`, `report-uri`, `sandbox`, и уже расходится между страницами. Заголовки из [server.py:57-63](../server.py#L57) к HTML не применяются, потому что HTML отдаёт хостинг. Дополнительно `X-XSS-Protection: 1; mode=block` ([server.py:62](../server.py#L62)) устарел и в современных браузерах не поддерживается.

## Шаги

1. Вынести CSP в HTTP-заголовок на уровне хостинга. Для Apache — `.htaccess` в корне; для nginx — `add_header Content-Security-Policy "..." always;`.
2. Собрать политику из текущей `<meta>` (не расширять список источников), добавить `frame-ancestors 'self'` вместо `X-Frame-Options` (или в дополнение).
3. Убрать `X-XSS-Protection` из `server.py`.
4. Оставить `<meta>` CSP как аварийный фолбэк, но синхронизировать его текст с заголовком.
5. Проверить, не блокируется ли что-то из работающего сейчас: Метрика, виджет Яндекс.Справки, шрифты Google, запросы к API бэкенда.

## Критерий готовности

Политика приходит заголовком, сайт работает без новых нарушений CSP, консоль чистая.

## Проверка

- `curl -I https://voltgroup-spb.ru/` → в ответе есть `content-security-policy`.
- Открыть каждую страницу с открытой консолью → нет сообщений «Refused to load / Refused to connect».
- Проверить работоспособность: Метрика (счётчик в реальном времени), виджет рейтинга, форма заявки, кабинет.
- `curl -I https://voltgroup-bot.onrender.com/ping` → нет `X-XSS-Protection`.
