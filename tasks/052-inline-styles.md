В карточке 050 измерялись только 138 в `index.html`; фактический объём по проекту в 4,9 раза больше — поэтому работа выносится в отдельную карточку и делается этапами.

**Чем это мешает.** Инлайн-стиль имеет максимальную специфичность: любая правка дизайна требует лезть в разметку, а часть решений продублирована в обход токенов. Пример: главная CTA калькулятора ([estimate.html:428](../estimate.html#L428)) несёт `background: linear-gradient(135deg, #10B981, #059669)`, `box-shadow: 0 0 20px rgba(16,185,129,0.35)` и `font-weight: 700` — при том что в `:root` уже есть токены свечения (Проход 3) и класс `.btn-primary`.

## Шаги

1. **Только `index.html` (138).** Сгруппировать инлайн-стили по повторяющимся наборам: одинаковые `margin-top`, `text-align`, `max-width`, `grid-template-columns` — в классы `static/css/style.css`. Разовые подстройки одного элемента оставить, но проверить, не дублируют ли они уже существующий класс.
2. За подход — **10–15 штук**, после каждого подхода: замер остатка + визуальная проверка страницы.
3. Повторять по файлам в порядке убывания: `engineering/` → `install/` → `bugry`/`murino` → `contacts/` → `estimate.html` → юридические → `works.html` → `client/index.html`.
4. При выносе **использовать существующие токены** (`--space-*`, `--fs-*`, `--shadow-*`, `--glow-*`), а не вводить новые значения.
5. Кэш-бэстинг: при каждой правке `style.css` синхронно поднимать `?v=` **на всех 12 страницах** (имена и текущая версия — [AGENTS.md](../AGENTS.md) §2.4; отсутствие рассинхрона проверяет `tools/check.py`).

| Показатель | Цель |

| Инлайн-стилей по проекту | ≤ 250 (было 676) |

| Токены | новые значения в CSS не введены, используются существующие |

## Проверка

1. Замер до/после — одной командой, вывод в журнал:
   ```powershell
   Get-ChildItem -Recurse -Filter *.html | ForEach-Object { "{0,5}  {1}" -f ([regex]::Matches((Get-Content $_.FullName -Raw), '\sstyle="')).Count, $_.FullName }
   ```
2. `python tools/check.py` → без новых ошибок (синхронность `?v=`).
3. Визуальная проверка каждой затронутой страницы: 1440, 1024, 768, 390 px + промежуточные 600, 900, 1150 px.
4. Отдельно проверить динамические блоки: галерея `works.html`, прайс-аккордеоны `install/`/`engineering/`, блок отзывов, модальные окна документов в калькуляторе — они собираются скриптом, и инлайн-стили там тоже есть.
5. `git diff` — убедиться, что не переформатированы чужие блоки (§2.5 AGENTS.md).

## Что НЕ делать

- Не менять палитру, шрифты и структуру страниц.
- Не выносить всё за один подход: инлайн-стиль побеждает класс, при массовом переносе поведение меняется незаметно.
- Не править логику JS: только разметка и CSS.
- Не трогать `?v=` без синхронного обновления на всех 12 страницах.
