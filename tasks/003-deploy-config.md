# Задача 003 — Воспроизводимый деплой бэкенда

**Пункт аудита:** № 3 (🔴 критично) · из [AUDIT.md](../AUDIT.md)
**Статус:** ⏳ не начато
**Файлы:** `server.py`, новый `render.yaml` (или `Procfile`)

## Проблема

`app.run(host='127.0.0.1', port=8000)` ([server.py:635](../server.py#L635)) — порт из `$PORT` не читается, на хостинге приложение не поднимется. `gunicorn` есть в зависимостях, но команда запуска нигде не зафиксирована: рабочая конфигурация существует только в панели хостинга и не восстановится при пересоздании сервиса.

## Шаги

1. Создать `render.yaml` с командой:
   `gunicorn -w 1 -k gthread --threads 8 --bind 0.0.0.0:$PORT --access-logfile - server:app`
   (один воркер — требование задачи 002).
2. Указать в файле переменные окружения **без значений**: `BOT_TOKEN`, `CHAT_ID`, `SHEET_URL`, `GOOGLE_CREDENTIALS`, `TELEGRAM_SECRET_TOKEN`.
3. Переписать блок `__main__` так, чтобы он читал `os.environ.get('PORT', 8000)` — для локального запуска.
4. Проверить, что `gspread` и остальные зависимости есть в [requirements.txt](../requirements.txt).

## Критерий готовности

Деплой поднимается по файлу из репозитория, без ручных настроек в панели. `/ping` отвечает `{"status": "awake"}`.

## Проверка

- `python -c "import ast; ast.parse(open('server.py',encoding='utf-8').read())"`.
- Локально: `python server.py` → сервер слушает 8000; `curl http://127.0.0.1:8000/ping` → `awake`.
- После деплоя: `curl https://voltgroup-bot.onrender.com/ping`.
- Пересоздать сервис из репозитория (или проверить в режиме предпросмотра) — конфигурация подхватывается автоматически.
