# Задача 013 — Работа по `file://` или честное предупреждение

**Пункт аудита:** № 16 (🟠 важно) · из [AUDIT.md](../AUDIT.md)
**Статус:** ⏳ не начато
**Файлы:** `README.md`, возможно `estimate.html`, `works.html`

## Проблема

README советует открывать `index.html`/`estimate.html` двойным кликом (стр. 138-145), но при `file://` браузер блокирует `fetch('./static/data/prices.json')` ([estimate.html:565](../estimate.html#L565)) и `fetch('./gallery/gallery-config.json')` ([works.html:452](../works.html#L452), [index.html:917](../index.html#L917)). Калькулятор показывает «❌ Не удалось загрузить прайс-лист», галерея — пустое состояние, и человек ищет ошибку в коде.

## Шаги (достаточно одного варианта, рекомендуется 1+2)

1. Исправить README: указать запуск через локальный HTTP-сервер (`python -m http.server 8000`) как обязательный шаг (входит в задачу 004).
2. Создать `tools/serve.cmd` (Windows) и `tools/serve.sh` — одна строка запуска сервера, чтобы «открыть проект» было одной командой.
3. Дополнительно улучшить сообщение об ошибке загрузки прайса: если протокол `file:`, писать прямо «откройте через HTTP-сервер, по `file://` браузер блокирует загрузку данных» ([estimate.html:599](../estimate.html#L599)).
4. При желании — встроенный fallback-набор цен в `estimate.html` на случай недоступности JSON (это же закрывает часть задачи 017).

## Критерий готовности

Человек, открывший проект впервые, не тратит время на диагностику: либо всё работает, либо сообщение прямо говорит, что делать.

## Проверка

- Открыть `estimate.html` по `file://` → видно понятное сообщение про HTTP-сервер (а не только «Не удалось загрузить»).
- Запустить `tools/serve.cmd` → `http://localhost:8000/estimate.html` → прайс загружается, галерея на главной работает.
