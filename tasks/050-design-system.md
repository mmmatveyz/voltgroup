# Задача 050 — Привести дизайн к системе: отступы, типографика, тени, breakpoints

**Направление:** дизайн-система · добавлена после аудита (07.10.2026)
**Статус:** ⏳ не начато (делать после [046](046-estimate-to-lead.md)–[049](049-loading-skeletons.md): правка затрагивает весь CSS и требует визуальной проверки каждой страницы)
**Файлы:** `static/css/style.css` (2692 строки), инлайн-стили в HTML

## Что не так: замеры

Дизайн сделан со вкусом — палитра выдержана, контраст на уровне AAA (cyan на тёмном — 12,93:1), нет следов шаблонизаторов, есть фирменный приём с инженерной сеткой. Но **системы нет**: одни и те же решения принимались многократно и каждый раз чуть по-разному.

| Показатель | Сейчас | У системного дизайна | Что это даёт |
|---|---|---|---|
| Уникальных значений `padding`/`margin`/`gap` | **95** | 6–8 из шкалы | Уходит разнобой между секциями |
| Уникальных `font-size` | **41** (много отличающихся на 0,02rem) | 6–8 | Главный источник «чуть-чуть не так» |
| Уникальных `box-shadow` | **51** | 3–4 уровня глубины | Появляется логика «что выше, что ниже» |
| Breakpoints | **8** (380…1200) | 4 | Предсказуемый адаптив между точками |
| `!important` | **64** | единицы | Признак борьбы со специфичностью |
| Инлайн-стилей в `index.html` | **138** | ~0 | Решения уходят из разметки в CSS |

**Важно:** шкала отступов уже объявлена в переменных — `--space-xs`…`--space-4xl` — но в правилах почти не используется. То есть идея токенов была, её просто не довели.

**Ключевой тезис:** проблема не в том, что «выглядит плохо». Проблема в несогласованности мелких решений. Это отличает «сайт, сделанный с душой руками» от «сайта, сделанного профессионалом»: первый вызывает симпатию, второй — доверие. Для подрядчика с чеком 100+ тысяч второе важнее, потому что качество щита на фото клиент оценить не может и судит по сайту.

## Принципы работы

1. **Никакого редизайна.** Визуальный язык (палитра, dark-tech, неон, инженерная сетка) **не меняется**. Приводятся к порядку только числовые значения.
2. **Менять по одному типу за подход.** Один проход — одна категория (сначала типографика, потом отступы, потом тени). Не смешивать.
3. **Проверять визуально каждую страницу после каждого прохода** на четырёх ширинах: **1440, 1024, 768, 390 px**. Без этого правка превратится в регрессию.
4. **Ничего не удалять из переменных.** `--space-*` уже есть — использовать их, а не вводить новые.
5. **Фиксировать замеры «до/после»** в журнале: число уникальных значений — измеримый критерий, по нему видно прогресс.

## Шаги

### Проход 1 — типографика (самый заметный)

1. Выписать фактические размеры шрифтов: `grep -o 'font-size:[^;]*' static/css/style.css | sort -u`.
2. Определить шкалу из 6–8 значений. Ориентир (подобрать под текущий вид, не ломая иерархию):
   - `0.75rem` — подписи, бейджи, мелкие пометки;
   - `0.875rem` — вспомогательный текст;
   - `1rem` — основной текст;
   - `1.125rem` — лид-абзац;
   - `1.5rem` — заголовок карточки / h3;
   - `2rem` — h2;
   - `2.5rem` — h1 на десктопе;
   - `clamp(...)` — только для h1/h2, чтобы не плодить варианты.
3. Заменить размеры, отличающиеся на 0,01–0,03rem, на ближайшее значение шкалы. **Иерархию сохранить:** если h3 был больше h2, это надо заметить и решить отдельно, а не «выровнять» механически.
4. Объявить шкалу переменными (`--fs-xs`…`--fs-3xl`) и использовать их.
5. Проверить `line-height`: сейчас 9 уникальных значений — свести к 3 (плотный для заголовков, обычный для текста, свободный для лидов).

### Проход 2 — отступы и вертикальный ритм

6. Выписать уникальные значения `padding`/`margin`/`gap` (95 штук).
7. Использовать **существующую** шкалу `--space-xs`…`--space-4xl`; если в ней нет нужного шага — добавить один, а не вводить произвольное значение.
8. Особое внимание — **вертикальным отступам секций.** Именно они дают ощущение «ровного» сайта. Сейчас `padding-top` для секций задаётся через `!important` в трёх медиазапросах (90px → 100px → 120px) — это костыль под фиксированную шапку. Заменить на переменную высоты шапки: `padding-top: var(--header-height)` с соответствующими значениями в медиазапросах, без `!important`.
9. Заменить горизонтальные `padding: 0 10px !important` / `0 12px` у `.container` на одно значение из шкалы.

### Проход 3 — тени и глубина

10. Свести 51 тень к 3–4 уровням: `--shadow-sm` (наведение на мелкий элемент), `--shadow-md` (карточка), `--shadow-lg` (модальное окно, выпадающее меню), при необходимости `--shadow-glow` для неоновых акцентов (у бренда есть свечение — сохранить его как отдельный уровень, а не смешивать с тенями).
11. Заменить по файлу, сохранив у неоновых элементов акцентное свечение.

### Проход 4 — breakpoints

12. Свести 8 точек (`380, 400, 480, 540, 640, 740, 768, 860, 992, 1080, 1200`) к четырём: **480** (узкий телефон), **768** (планшет), **1024** (небольшой ноутбук), **1280** (десктоп).
13. **Осторожно:** перед слиянием проверить, что при переносе правила не начнут конфликтовать (например, правило с 740px и правило с 768px могут противоречить друг другу). В спорных случаях смотреть фактический вид, а не формальную логику.
14. После сведения — проверить поведение на ширинах **между** новыми точками: 600, 900, 1150 px. Именно там вылезают поломки, которых раньше не было.

### Проход 5 — убрать инлайн-стили

15. В `index.html` 138 инлайн-стилей. Вынести повторяющиеся в классы. Разовые (например, тонкая подстройка отступа у одного элемента) — оставить, но проверить, не дублируют ли они класс.
16. Это самый трудоёмкий и самый рискованный проход: инлайн-стиль имеет максимальную специфичность, и при переносе в класс поведение может измениться. Делать по 10–15 штук за подход с визуальной проверкой.

### Проход 6 — заменить фиксированные размеры

17. Найти 25 фиксированных `height` в пикселях. Для карточек с изображениями и текстовыми блоками заменить на:
    - `aspect-ratio` — для изображений и медиа-контейнеров;
    - `min-height` вместо `height` — для блоков с текстом.
18. **Причина:** фиксированная высота ломает вёрстку при увеличении системного шрифта, длинном тексте и масштабе 125%. Это не косметика, а доступность: часть посетителей видит испорченную страницу.

## Критерий готовности

| Показатель | Цель |
|---|---|
| Уникальных `font-size` | ≤ 10 |
| Уникальных значений отступов | ≤ 25 (включая составные) |
| Уникальных `box-shadow` | ≤ 6 |
| Breakpoints | 4 |
| `!important` | ≤ 10 |
| Инлайн-стилей в `index.html` | ≤ 20 |
| Фиксированных `height` в px | ≤ 5 (только там, где оправдано) |
| Внешний вид | не изменился: та же палитра, тот же характер |

**Главный критерий:** сайт выглядит **так же**, только ровнее. Если после правок заметно «стало другим» — значит что-то переделали сверх задачи.

## Проверка

1. `python tools/check.py` → без ошибок (проверяется синхронность `?v=`, поэтому версию стилей обновить на всех 10 страницах).
2. Замеры «до/после» по каждому проходу — записать в [AGENT_STATE.md](../AGENT_STATE.md): было N, стало M.
3. **Визуальная проверка после каждого прохода** на ширинах **1440, 1024, 768, 390 px** — плюс промежуточные 600, 900, 1150 px.
4. Пройти все страницы: главная, `/install/`, `/engineering/`, `/contacts/`, `works.html`, `estimate.html`, юридические, `client/index.html`.
5. Проверить калькулятор: таблицы, аккордеоны, кнопки, модальные окна документов.
6. Проверить блок отзывов и галерею (они заполняются скриптом — легко пропустить).
7. Проверить тёмную тему в реальном браузере на мобильном (не только в DevTools).
8. Убедиться, что `prefers-reduced-motion` и `focus-visible` продолжают работать.
9. Сравнить скриншоты «до/после» ключевых экранов — глазами, попарно.

## Что НЕ делать

- **Не менять палитру, шрифты и визуальный язык.** Задача — порядок, не редизайн.
- Не переписывать `style.css` целиком: только точечные замены.
- Не менять порядок секций и структуру страниц.
- Не трогать логику: правки только в CSS и в вынесении инлайн-стилей.
- Не делать все проходы за один раз.
- Не «улучшать» попутно то, о чём не просили (см. [AGENTS.md](../AGENTS.md) §2.5).

## Почему это стоит делать

Клиент не может оценить качество электромонтажа по фотографии. Он оценивает косвенно: по опрятности сайта, по договору, по аккуратности документов. Несогласованные отступы и «почти одинаковые» размеры шрифта он не назовёт словами, но почувствует как «сделано на скорую руку» — и перенесёт это ощущение на работу.

Обратное тоже верно: ровный, системный сайт создаёт ощущение, что и щит собран аккуратно.
