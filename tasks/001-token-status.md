## Проблема

`/get-status` отдавал адрес объекта, сумму договора, внесённую сумму и остаток по одному числовому `id` без какой-либо аутентификации. ID последовательные, значит перебором `?id=1..999` можно было получить финансовые данные всех клиентов.

## Шаги

1. Добавить в `COLUMNS_MAP` ключ `'token': 8` ([server.py:76-82](../server.py#L76)).
2. Генерировать токен при создании объекта через `secrets.token_urlsafe(16)` и писать в колонку 8: создание из бота ([server.py:581](../server.py#L581)) и команда `/new` ([server.py:596](../server.py#L596)).
3. В `get_status` принимать `t` (или `token`) из GET и POST, при отсутствии — 403 ([server.py:322-335](../server.py#L322)).
4. Сравнивать через `secrets.compare_digest` с учётом пустого значения в ячейке ([server.py:345](../server.py#L345)).
5. В ссылке для клиента подставлять токен, при отсутствии — генерировать и сохранять ([server.py:486-502](../server.py#L486)).
6. В кабинете читать `t` из URL и передавать в запрос; при отсутствии `id` или `t` показывать ошибку доступа ([client/index.html:285-320](../client/index.html#L285)).

## Критерий готовности

Кабинет без токена или с неверным токеном не получает данных; с корректным — получает.

## Проверка

- `python -c "import ast; ast.parse(open('server.py',encoding='utf-8').read())"` → ошибок нет.
- `curl "https://voltgroup-bot.onrender.com/get-status?id=1"` → 403 «Отсутствует ключ доступа».
- `curl "https://voltgroup-bot.onrender.com/get-status?id=1&t=неверный"` → 403.
- `curl "https://voltgroup-bot.onrender.com/get-status?id=<реальный>&t=<токен из таблицы>"` → `success`.
- Прогнать существующие объекты: у них колонка 8 пустая → ссылка из бота должна сгенерировать токен и сохранить.

## Остаток

- **[server.py:497-498](../server.py#L497)** — если объект не найден (`cell` пустой), код всё равно генерирует случайный токен и отправляет мастеру ссылку. Такая ссылка гарантированно даст 403, и мастер будет думать, что сломан кабинет. Нужно отправлять сообщение «объект №X не найден» и прерывать обработку.
- Пункт 2 из аудита (состояние бота) **не закрыт**: он про `user_states`, а не про токен.
