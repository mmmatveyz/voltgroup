# Задача 012 — Фотоотчёты: реализовать или убрать

**Пункт аудита:** № 9 (🟠 важно) · из [AUDIT.md](../AUDIT.md)
**Статус:** ⏳ не начато (нужно решение: реализовать или убрать)
**Файлы:** `server.py`, `README.md`, возможно `client/index.html`

## Проблема

Фронтенд и схема таблицы к фотоотчётам готовы, приёма фото в боте нет: вебхук обрабатывает только `message.text` ([server.py:514](../server.py#L514)), а `COLUMNS_MAP['photo']` ([server.py:79](../server.py#L79)) и рендер в кабинете ([client/index.html:336-364](../client/index.html#L336)) остаются неиспользованными. README обещает функцию (стр. 87). Кабинет заказчика всегда показывает плейсхолдер.

## Вариант А — реализовать

1. Добавить в вебхук обработку `data["message"].get("photo")`: брать `file_id` последнего (максимального) размера.
2. Получать путь через `getFile`, формировать постоянный URL.
3. Хранить ссылки в колонке 7 через запятую **без пробелов** — кабинет разбирает значение именно так ([client/index.html:337](../client/index.html#L337)).
4. При нескольких фото накапливать список, не перезаписывая предыдущие.
5. Учесть лимит длины ячейки: при большом числе ссылок предусмотреть обрезку или отдельный лист.

## Вариант Б — убрать

1. Удалить описание фотоотчётов из README.
2. Либо оставить в интерфейсе бота кнопку, но с явным сообщением «функция в разработке».

## Критерий готовности

Обещанное в README работает, либо README не обещает несуществующего. Плейсхолдер в кабинете либо сменяется фото, либо описан как временный.

## Проверка

- Синтаксис: `python -c "import ast; ast.parse(open('server.py',encoding='utf-8').read())"`.
- Отправить в бот фото → в колонке 7 появилась ссылка → открыть кабинет → фото отображается.
- Отправить два фото подряд → в ячейке две ссылки через запятую, в кабинете две картинки.
- Проверить, что не-HTML символы и `&` в URL не ломают разбор в JS.
