# Задача 012 — Фотоотчёты: реализовать или убрать

**Пункт аудита:** № 9 (🟠 важно) · из [AUDIT.md](../AUDIT.md)
**Статус:** ✅ завершено (07.10.2026)
**Файлы:** `server.py`, `.env.example`, `render.yaml`, `tools/check.py`


## Проблема

Фронтенд и схема таблицы к фотоотчётам готовы, приёма фото в боте нет: вебхук обрабатывает только `message.text`, а `COLUMNS_MAP['photo']` и рендер в кабинете остаются неиспользованными. Кабинет заказчика всегда показывает плейсхолдер «Фотографии с объекта скоро появятся здесь».

**Обновление 06.10.2026.** Правка README по пункту 4 аудита уже выполнена (задача [004](004-readme-fix.md)): описание больше **не обещает загрузку фото в бот**, формулировка заменена на «Фотогалерея объекта из ссылок Google Таблицы» ([README.md:105](../README.md#L105)). То есть расхождения документации с кодом больше нет.

**Что осталось решить:** механика для мастера. Сейчас попасть фото в колонку 7 можно только вручную через Google Таблицу. Вариант «убрать» в части README уже фактически выполнен, поэтому выбор сузился: либо реализовать приём фото в боте, либо явно закрыть кнопку в интерфейсе сообщением о том, что функция недоступна.

## Шаги

### Вариант А — реализовать приём фото

1. Добавить в вебхук обработку `data["message"].get("photo")`: брать `file_id` последнего (максимального) размера.
2. Получать путь через `getFile`, формировать постоянный URL.
3. Хранить ссылки в колонке 7 через запятую **без пробелов** — кабинет разбирает значение именно так ([client/index.html:337](../client/index.html#L337)).
4. При нескольких фото накапливать список, не перезаписывая предыдущие.
5. Учесть лимит длины ячейки Google Таблицы (50 000 символов): при большом числе ссылок предусмотреть обрезку или отдельный лист.

### Вариант Б — закрыть функцию явно

1. В интерфейсе бота, если кнопка фотоотчёта есть, отвечать сообщением «функция в разработке» вместо молчания.
2. В [client/index.html](../client/index.html) заменить плейсхолдер на текст, понятный клиенту: фото добавляются мастером вручную и появятся после первого отчёта.
3. Зафиксировать решение в [AGENT_STATE.md](../AGENT_STATE.md), чтобы вопрос не поднимался заново.

## Критерий готовности

Механика фотоотчётов либо работает end-to-end (фото из бота → колонка 7 → кабинет), либо явно закрыта в интерфейсе и описана в документации без обещаний.

## Проверка

- Синтаксис: `python -c "import ast; ast.parse(open('server.py',encoding='utf-8').read())"`.
- Отправить в бот фото → в колонке 7 появилась ссылка → открыть кабинет → фото отображается.
- Отправить два фото подряд → в ячейке две ссылки через запятую, в кабинете две картинки.
- Проверить, что не-HTML символы и `&` в URL не ломают разбор в JS.
