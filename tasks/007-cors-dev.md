# Задача 007 — CORS: разрешить разработку и превью

**Пункт аудита:** № 5 (🟠 важно) · из [AUDIT.md](../AUDIT.md)
**Статус:** ✅ завершено (2026-10-06)
**Файлы:** `server.py`, `.env.example`

## Проблема

`ALLOWED_ORIGINS` содержит только прод-домены ([server.py:39-42](../server.py#L39)). При открытии сайта с `localhost`, с превью-домена хостинга или с GitHub Pages все запросы к `/send-message`, `/get-status`, `/ping` блокируются браузером. На стороне Flask это не логируется — ошибку ищут в JS.

## Шаги

1. Читать список из переменной окружения `ALLOWED_ORIGINS` (через запятую), с текущими прод-доменами как значение по умолчанию.
2. Добавить в дефолт локальные адреса разработки: `http://localhost:8000`, `http://127.0.0.1:8000`, `http://localhost:5500`.
3. Задокументировать переменную в `.env.example` (задача 033) и в `docs/DEPLOY.md`.
4. Сузить область действия `CORS(app, resources={r"/*": ...})` до маршрутов, которым CORS действительно нужен, если это не ломает сайт.

## Критерий готовности

С локального сервера форма заявки и кабинет работают; прод не затронут.

## Проверка

- `python -c "import ast; ast.parse(open('server.py',encoding='utf-8').read())"`.
- Локально: `python -m http.server 8000`, открыть `index.html`, отправить тестовую заявку → в Telegram приходит уведомление.
- Открыть кабинет локально с корректным `id` и `t` → данные загружаются.
- Проверить, что запрос с постороннего origin по-прежнему блокируется.
