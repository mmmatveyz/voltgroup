# Задача 049 — Скелетоны загрузки вместо текста «Загрузка…»

**Направление:** UX · добавлена после аудита (07.10.2026)
**Статус:** ⏳ не начато
**Файлы:** `works.html`, `index.html`, `install/index.html`, `engineering/index.html`, `static/css/style.css`

## Проблема

Прайс и галерея подгружаются скриптом из JSON, а пока грузятся — на экране только текстовая заглушка:

| Файл | Строка | Что показывается |
|---|---|---|
| [works.html](../works.html#L327) | 327 | `⏳ Загрузка портфолио...` |
| [index.html](../index.html#L303) | 303 | `⏳ Загрузка прайс-листа...` |
| [install/index.html](../install/index.html) | ~540 | то же |
| [engineering/index.html](../engineering/index.html) | ~540 | то же |

На мобильном интернете (основной сценарий — клиент или мастер на объекте) между первым рендером и появлением данных проходит заметное время: браузер скачивает JSON, затем скрипт строит 14 карточек галереи или несколько аккордеонов с 69 строками прайса. Всё это время страница выглядит **пустой с текстом** — как сломанная.

**Скелетон** — серые блоки-плашки, повторяющие форму будущего контента. Пользователь понимает, что данные загружаются, и видит структуру страницы заранее. Это стандартный приём (так делают ленты новостей, маркетплейсы, видеосервисы).

## Дополнительная проблема, которую закроет эта же правка

Карточки галереи создаются скриптом с классом `gallery-item`, но анимация появления включается через `IntersectionObserver` только для элементов, существовавших в DOM на момент подписки ([works.html](../works.html) — код наблюдения выполняется до/независимо от вставки карточек). Из-за этого возможен случай, когда контент загрузился, но остаётся с нулевой прозрачностью — «загрузилось, но не видно». При переходе на скелетоны следует явно добавлять класс видимости к вставленным карточкам, как это сделано для отзывов (`review-card fade-in visible`).

## Шаги

### 1. Базовые стили скелетона в `static/css/style.css`

```css
/* Скелетоны загрузки: показываются до появления данных из JSON */
.skeleton {
    background: linear-gradient(90deg,
        rgba(255, 255, 255, 0.04) 25%,
        rgba(255, 255, 255, 0.09) 37%,
        rgba(255, 255, 255, 0.04) 63%);
    background-size: 400% 100%;
    animation: skeleton-shimmer 1.4s ease infinite;
    border-radius: var(--radius-md);
}

@keyframes skeleton-shimmer {
    0%   { background-position: 100% 50%; }
    100% { background-position: 0 50%; }
}

/* Уважение к настройкам доступности: убрать мерцание */
@media (prefers-reduced-motion: reduce) {
    .skeleton { animation: none; background: rgba(255, 255, 255, 0.06); }
}

.skeleton-card { height: 220px; }
.skeleton-row  { height: 44px; margin-bottom: 10px; }
.skeleton-line { height: 12px; }
```

Класс `skeleton-card` подогнать под фактические пропорции карточек галереи (в текущем CSS — `.gallery-item` / `.gallery-img`), `skeleton-row` — под высоту строки прайса. **Проверить по фактическим стилям, а не угадывать**: если карточка выше 220 px, поправить, иначе при подмене будет скачок вёрстки (layout shift), а он вредит и восприятию, и Core Web Vitals.

### 2. Разметка заглушек

**Галерея** (`works.html`): заменить `<p>⏳ Загрузка портфолио...</p>` на контейнер с шестью карточками-скелетонами, повторяющий сетку галереи:

```html
<div id="gallery-skeleton" class="gallery-grid" aria-hidden="true">
    <div class="skeleton skeleton-card"></div>
    ... (6 штук)
</div>
<p id="loading-text" class="sr-only">Загрузка портфолио…</p>
```

**Прайс** (`index.html`, `install/index.html`, `engineering/index.html`): заменить `<p>⏳ Загрузка прайс-листа...</p>` на 4-5 строк-скелетонов.

Текстовую заглушку **не удалять полностью**: оставить для скринридеров, скрыв визуально (класс `sr-only` или `visually-hidden`; если такого класса в проекте нет — добавить). Так пользователи программ чтения с экрана получат понятное «Загрузка прайс-листа», а зрячие увидят плашки.

### 3. Скрывать скелетон при появлении данных

В каждом скрипте, который заполняет контейнер, после успешного рендера удалить скелетон:

```javascript
const skeleton = document.getElementById('gallery-skeleton');
if (skeleton) skeleton.remove();
```

**Обязательно и в ветке ошибки** (`fetch` не удался): иначе при недоступном `gallery-config.json` пользователь будет бесконечно смотреть на мерцающие плашки. В этом случае показать понятный текст ошибки, а скелетон убрать. Сейчас в [works.html](../works.html) ошибка уже обрабатывается блоком с сообщением — проверить, что скелетон при этом скрывается.

### 4. Проверить видимость вставленных карточек

Убедиться, что карточки галереи и строки прайса, созданные скриптом, **видимы сразу**, без ожидания `IntersectionObserver`. Если используется класс анимации (`fade-in`), добавлять вместе с `visible` при создании элемента. Проверка: загрузить страницу с медленной сетью и убедиться, что карточки появляются видимыми.

## Критерий готовности

При загрузке страниц с прайсом и галереей вместо одинокого текста видны плашки, повторяющие форму контента; после подгрузки данных плашки исчезают, контент виден сразу. При недоступности JSON показывается сообщение об ошибке, а не бесконечные плашки.

## Проверка

1. `python tools/check.py` → без ошибок.
2. Локально через `tools/serve.cmd`, **DevTools → Network → Slow 3G**: открыть `/works.html` → видна сетка плашек; после загрузки — карточки, плашки исчезли.
3. То же для `/install/`, `/engineering/` и главной (блок прайса).
4. **Ошибка загрузки:** в DevTools включить **Offline**, перезагрузить `/works.html` → плашки исчезли, показано сообщение об ошибке.
5. **Медленная сеть:** дождаться появления карточек → проверить, что они видимы (не прозрачные), и что нет резкого скачка разметки при подмене.
6. `prefers-reduced-motion`: в DevTools → Rendering → эмулировать «prefers-reduced-motion: reduce» → мерцание плашек отсутствует.
7. Проверить, что скринридер читает текст «Загрузка…» (визуально скрытый элемент не должен иметь `display: none`).

## Что НЕ делать

- Не менять механизм загрузки данных (fetch и построение остаются как есть) — правка только про состояние загрузки.
- Не добавлять новых зависимостей и внешних скриптов.
- Не убирать обработку ошибок: она уже есть, и её нужно сохранить.
- Не делать скелетоны «на глаз» по высоте — подгонять под фактические размеры, чтобы не было скачка вёрстки.
