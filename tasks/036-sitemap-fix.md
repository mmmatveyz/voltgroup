# Задача 036 — Sitemap, `Clean-param` и актуальный `lastmod`

**Направление:** SEO · техническая часть · из [AUDIT.md](../AUDIT.md)
**Статус:** ⏳ не начато (часть пунктов подтверждена замерами 06.10.2026)
**Файлы:** `sitemap.xml`, `robots.txt`

## Что подтвердили замеры 06.10.2026

- **Canonical и sitemap согласованы.** Проверено посимвольно: у всех 9 URL из sitemap canonical на странице указывает ровно на тот же адрес. `install/index.html → /install/`, `engineering/index.html → /engineering/`, `contacts/index.html → /contacts/`. Расхождений нет — править canonical не нужно.
- **Source = счётчик Метрики.** Все записи в Вебмастере пришли как «Счётчик Метрики», **ни одной — из sitemap**. Косвенный признак, что sitemap как источник обхода не сработал: нужно проверить раздел «Файлы Sitemap» и, возможно, переотправить файл.
- **Мусорные варианты URL.** Яндекс держит в исключённых `/?_ym_debug=1` — это отладочный параметр Метрики. В `robots.txt` нет `Clean-param`, поэтому вариант не склеивается автоматически.
- **`lastmod` одинаковый у всех страниц** — `2026-09-29`, хотя фактически страницы менялись в разное время (последние правки — 06.10.2026).

## Проблема (исходная)

**1. Три URL в sitemap не соответствуют файлам.** Sitemap содержит:

```
https://voltgroup-spb.ru/install/
https://voltgroup-spb.ru/engineering/
https://voltgroup-spb.ru/contacts/
```

Файлы на диске лежат по путям `install/index.html`, `engineering/index.html`, `contacts/index.html`. Для хостинга со `index.html` в качестве индексного файла это разрешается в тот же адрес — **но только если сервер настроен отдавать `index.html` по каталогу без слэша и без 301 на `.html`**. Если этого нет, Яндекс получит 404 по трём URL из девяти, и разделы не проиндексируются.

**2. Один и тот же `lastmod` у всех страниц** — `2026-09-29`, при том что страницы менялись в разное время и есть более свежие правки. Одинаковая дата на всё выглядит как «залили одним куском и забыли», ослабляя сигнал свежести.

**3. В sitemap нет `priority`/`changefreq`-логики** — они проставлены, но одинаково неинформативно; это допустимо, но заметно.

## Шаги

0. **Проверить, что sitemap виден роботу:** Яндекс.Вебмастер → Индексирование → Файлы Sitemap → загружен ли `https://voltgroup-spb.ru/sitemap.xml`, статус обработки, сколько URL найдено. Если файл не в списке — добавить его. Это связано с [044](044-recrawl.md).
0.1. **Добавить `Clean-param` в [robots.txt](../robots.txt)** для отладочных параметров Метрики, чтобы варианты вида `/?_ym_debug=1` склеивались с главной:
   `Clean-param: _ym_debug /`
   Проверить, не нужно ли добавить и другие служебные параметры (UTM-метки Яндекс обрабатывает сам).
   ⚠️ `Clean-param` действует только в Яндексе. Для Google склейку обеспечивает `rel="canonical"`, который уже есть, — дополнительных правок не требуется.
1. **Проверить резолвинг URL без `.html`.** Открыть `https://voltgroup-spb.ru/install/`, `/engineering/`, `/contacts/`, а также без слэша: `/install`. Убедиться, что отдаётся 200 и **без** редиректа на `index.html`. По замерам главная отдаёт 200 OK, вероятно и разделы тоже — проверить и зафиксировать.
2. Если отдаётся 404 или редирект на `.html` — привести sitemap к фактическим адресам либо настроить серверные правила и **закрепить один канонический вариант**, совпадающий с `rel="canonical"` на странице.
3. Обновить `lastmod` по фактическим датам последних изменений файлов (не позднее 06.10.2026).
4. Убедиться, что в sitemap нет страниц, которые не должны индексироваться (`client/index.html` там и нет — верно).
5. Проверить XML на валидность и соответствие схеме sitemap.org.

## Критерий готовности

Все 9 URL из sitemap открываются с кодом 200 и возвращают именно ту страницу, на которую указывает canonical. Даты `lastmod` отражают реальные изменения.

## Проверка

- Последовательно запросить все 9 URL из sitemap → всюду 200 и ожидаемый `<title>`.
- `python -c "import xml.dom.minidom;xml.dom.minidom.parse('sitemap.xml')"` → без ошибок.
- Яндекс.Вебмастер → «Индексирование → Файлы Sitemap» → после переобхода нет ошибок по URL.
- Валидатор: `https://www.xml-sitemaps.com/validate-xml-sitemap.html` или аналогичный.
